# Differential conformance harness

The server's accept/reject decisions and parsed metadata must match libAPG, the
canonical client-side implementation. This directory holds the tooling that
proves it.

## Layout

- `oracle/apg_oracle.c` — a small C program linking libAPG through its public
  headers. It prints one JSON object per invocation:
  - `parse <pkg.apg> <scratch-root>` — `parse_package()` verdict + metadata
    (the libAPG acceptance gate; does NOT execute package scripts),
  - `install <pkg.apg> <scratch-root>` — parse + `install_package_in_root()`
    (also requires `data/`; runs scripts in the scratch root — use with
    trusted corpora only),
  - `extract <pkg.apg> <scratch-root>` — `unarchive_package_in_root()` only,
  - `vercmp <a> <b>` — `ver_compare()` signum,
  - `depparse <constraint>` — `dep_constraint_parse()` + canonical form,
  - `keyring <dir> <pkg> <sig>` — `keyring_load()` + `keyring_verify()`.
- `oracle/apg_sigtool.c` — generates genuine libAPG-format signatures:
  - `keygen <seed-hex32> <out-secret.key> <out-public.key>` — deterministic
    keypair from a fixed seed (reproducible vectors),
  - `sign <secret.key> <pkg> <out.sig>` — signs with libAPG's exact
    libsodium streaming sequence (`crypto_sign_init/update/final_create`,
    i.e. **Ed25519ph**),
  - `verify <keyring-dir> <pkg> <sig>` — `keyring_verify()` JSON verdict.
  The vectors under `signatures/` were produced with this tool; the JVM
  verifier is asserted equal to the oracle's verdict on every scenario.
- `../src/test/resources/conformance/corpus/` — the committed archive corpus
  (valid, invalid, adversarial; generated programmatically, see
  `corpus-generator.py`).
- `../src/test/resources/conformance/goldens-*.json` — oracle outputs recorded
  at the pinned libAPG commit. The hermetic test
  `GoldenCorpusTest` replays them, so `./gradlew test` needs no libAPG.

## Building the oracle

Requires libAPG built from the pinned commit (see docs/libapg-compat.md) and
its dependencies. From a libAPG clone at `.agent/deps/libAPG` (or any prefix):

```sh
meson setup build --buildtype=release && meson compile -C build   # in the libAPG clone
gcc -O2 -std=gnu11 -I<libapg>/include -I<libsodium-prefix>/include \
    apg_oracle.c -o apg_oracle \
    -L<libapg>/build -lapg -L<libsodium-prefix>/lib -lsodium \
    -Wl,-rpath,<libapg>/build -Wl,-rpath,<libsodium-prefix>/lib
```

## Running the live differential test

```sh
./gradlew conformanceTest -PapgOracle=/path/to/apg_oracle
```

The task re-runs the oracle over the committed corpus and version/dependency
matrices and asserts the outputs still match the checked-in goldens. It is
skipped (with a loud message) when `-PapgOracle` is absent, so plain
`./gradlew test` stays hermetic. CI runs it against a freshly built libAPG at
the pinned commit.

## Regenerating goldens

Only do this after intentionally moving the libAPG pin, and review the diff:

```sh
./gradlew regenerateConformanceGoldens -PapgOracle=/path/to/apg_oracle
```

## Corpus provenance

All corpus archives are generated by `corpus-generator.py` (deterministic,
mtime=0, uid/gid=0) — no third-party fixtures are redistributed. The two
production-pool samples used elsewhere in tests (`.agent/fixtures/`) stay
outside the repo (they are the live deployment's packages).
